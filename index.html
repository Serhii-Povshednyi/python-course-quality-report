Python Course — Independent Quality Report

Date: August 15, 2026

Scope: the app's built-in Python interpreter, the authored curriculum content (1349+ exercises, 45 lessons, 6 languages), and the spaced-repetition scheduling algorithm

Methodology

The app runs learner-submitted code through a custom, from-scratch Python interpreter (not CPython, not a third-party library) — a deliberately limited but continuously growing subset of the language, scoped to exactly what the curriculum's own exercises need. The correctness of this interpreter — and, separately, two other non-code components (curriculum structure, the spaced-repetition algorithm) — was validated along three independent tracks, each with its own methodology, sharing no code and with no dependency of one result on another.

Shared principle for the Python interpreter: every candidate (an authored reference solution, a template-generated instance, or a randomly generated program) was run simultaneously through the app's own interpreter and through a system-installed CPython 3.12.3, with a bitwise comparison of the result (return value or printed text) or of error consistency (both must raise on equally invalid code). Validation ran through a temporary, isolated tool, not part of the app's permanent code — the dependency on a system Python installation exists only for the duration of one validation run.

Shared principle for curriculum structure: a full, non-sampled pass over every content file — no sampling.

Shared principle for the spaced-repetition algorithm: the real scheduler's output was checked against a separately written (not copied from the scheduler's own code) implementation of the same mathematical formula.

Process note: validation was run in several independent rounds, deliberately without referencing each other's results in advance, to keep each pass a genuine from-scratch check rather than a rubber stamp of the previous one. Earlier rounds (documented in the project's own change history) found and fixed a small number of real, narrow interpreter bugs — none of which affected any actual curriculum content, all confirmed fixed and re-validated before this report was compiled. The results below are from the final, most recent validation pass, run against the current state of the code with no known open issues.

Summary Results

Candidates were checked against an independent oracle (CPython for the interpreter; a separately derived formula for the spaced-repetition algorithm). For curriculum structure and localization, "candidate vs. oracle" doesn't apply — these are structural/content checks, not oracle comparisons — so they're reported separately, not folded into the combined total.

Details by Track

1. Python interpreter vs. CPython 3.12.3

Coverage spans every piece of code the app ever actually executes:

  • every "write the code" exercise in the main curriculum, including every authored alternative solution;
  • the full extended practice-mode content pool — both hand-authored exercises and parameterized templates (each template run across enough generated instances to cover its full declared parameter range, including both endpoints);
  • 300+ syntactically valid Python programs, randomly generated within the interpreter's supported language subset, combining loops, conditionals, functions (including default parameter values), classes and inheritance, list comprehensions, f-strings, boolean/type edge cases, and other constructs in combinations not present anywhere in the authored content.

Result: 636 out of 636 candidates matched CPython exactly. Zero discrepancies.

During the iterative validation process that led to this state, a small number of genuine interpreter bugs were found and fixed — each one narrow, each one confirmed to have never affected any actual curriculum exercise, and each one re-validated against live CPython after the fix:

  • a whole-number division result printing as an integer instead of Python's actual decimal-typed result (e.g. 11 instead of 11.0);
  • a rare floating-point rounding artifact in the remainder (%) operator on fractional operands;
  • boolean values not being treated as numerically equal to their integer counterparts in equality/membership checks (Python treats True/False as a subtype of int, so True == 1 and 1 in [True] are both expected to hold).

All three were found by the same randomized-testing methodology described above, fixed at the source, and covered by new permanent regression tests before this final validation pass — which itself found no further issues.

2. Curriculum structure

A full, non-sampled check of all 1349 exercise files and 45 lesson files:

  • every "write the code" exercise's reference solution was actually executed and checked against its expected result — 0 discrepancies;
  • no reference to a non-existent lesson or exercise anywhere in the curriculum's prerequisite graph — 0 found;
  • no duplicate identifier among the 1349 exercises (or the 60 extended-practice-mode pool entries) — 0 found;
  • localization: all 6 interface languages have exact parity in content string-key count and coverage (8118 keys each), 0 missing and 0 orphaned keys in any language, 0 untranslated (copy-pasted-from-Ukrainian) values among the keys actually used by content.

3. Spaced-repetition scheduling algorithm

1020 randomized scenarios — answer sequences of varying length (1 to 15 reviews), mixing correct/incorrect answers, long streaks, and randomized gaps between reviews (same-day up to 45 days), plus dedicated scenarios targeting the algorithm's maximum-interval cap and multi-decade date handling — 8917 individual review steps in total. Every step was independently recomputed from the algorithm's documented formula and checked against the real scheduler's actual output across every relevant field (ease factor, interval length, repetition/lapse counters, next-review date). The interval cap correctly engaged in several hundred of the steps designed to reach it, with no exceptions.

Result: 8917 out of 8917 — full match.

Conclusion

Out of 9553 candidates independently checked against an oracle (Python interpreter + spaced-repetition algorithm) — 0 discrepancies. A small number of genuine, narrow interpreter bugs were found and fixed during the validation process itself; none ever affected real curriculum content, and all are now covered by permanent regression tests and re-confirmed clean in this final pass. Curriculum-structure checks (1349 exercise files, 45 lessons) and localization checks (6 languages, 40,590 key comparisons) found no issues.
